# ADR-0012: Application shell and personal navigation (Phase 1E)

Status: **implemented; deviations F1–F9 accepted by the product owner; acceptance pending CI.** Engineering detail: [tenancy.md](../tenancy.md#phase-1e-shell-and-personal-navigation).
Extends ADR-0010 (1C) and ADR-0011 (1D).

Accepted sources:
- 0B: ADR-20 (`favorite`, `recent_item`, `view_state`, `account_preference`, `view_pin`).
- 0C: AZ-20 (personal navigation is a hint); T-39 with AT-108…114.
- 0D: PL-21 (eight bounded signals; parameters `FAVORITES_MAX`, `RECENT_ITEMS_MAX`, `RECENT_VISIT_COALESCE`, `VIEW_STATE_MAX_BYTES`, `VIEW_STATE_TTL`).
- 0E: RS-01…RS-65, IA-01…IA-28, IA-40…IA-47, DS-07/08/23/40/41, ST-08/41, A11Y-KB-06/07.

## Context

1E builds the permanent frame that every module renders inside. The 1C scope resolver, the 1D permission compiler, public IDs, the audit stack, and the existing UI primitives are reused. There is no parallel router, brand selector, authorization check, design system, or preference store.

## Decisions

| # | Topic | Decision |
|---|---|---|
| E1 | One route registry | `apps/web/src/shell/registry.ts` lists every route: pattern, shell kind (workspace, personal, minimal), section label, navigation placement, destination, scope sensitivity, later-phase marker, go-to command, shortcut, and one permission predicate. The sidebar, rail, Compact bottom bar and More sheet, breadcrumbs, page titles, the palette's Go to group, and go-to shortcuts all read it. `app-routes.tsx` maps every id to a page through one record, and a unit test proves full coverage, so there are no dead destinations. |
| E2 | Router and history | The existing history router gains per-entry state (tab-local scope, previous scope, sheet marker), push and replace per RS-21, and leave guards (RS-25: *Stay* / *Leave without saving*, Stay focused). Every navigational element is a real link; actions are buttons. |
| E3 | Shell layouts | Width classes are CSS media queries over DS-08 tokens (Compact < 600 ≤ Medium < 1024 ≤ Expanded < 1440 ≤ Wide); the JavaScript width hook uses the same numbers for behavior only (a test keeps them aligned). There is no user-agent detection. |
| E4 | Shell surfaces | Expanded/Wide: collapsible sidebar (device-remembered). Medium: icon-plus-label rail with Favorites/Recent flyouts. Compact: top bar, exactly five bottom slots (Home, Today, Inbox, My Work, More), a More sheet, and safe-area padding. On short viewports the bottom bar hides while scrolling down. Dialogs render through a portal, so no sticky surface can sit above a modal. |
| E5 | Scope (WSB-006) | The canonical 1C context resolver is extended in place. A URL token (`scope=all`, `brand:{id}`, `brands:{id},…`) is authoritative on scope-sensitive routes; otherwise the history entry's scope applies, then the per-device default (view state `shell.scope`), then the membership's last selection. Every brand is validated against the principal; inaccessible or foreign brands are dropped silently, narrowing the scope and never broadening it. The server returns the normalized token, and the client replaces the URL with it. Choosing a scope pushes history and stores the per-device default. Opening an authorized record of another brand switches the tab's scope (entry state), announces it, and offers *Back to previous scope*; browser Back restores page and scope together. |
| E6 | Brand marker (WSB-015) | One response shape `brand_marker` (`brand` with id, name, short name, colour, icon, archived; `workspace`; `unbranded`) and one `BrandMarker` component. The glyph is black or white, whichever contrasts more (≥ 4.5:1, swept in tests), and weak tiles get an outline. The 1D shared-records list now uses this shape. |
| E7 | Personal lists | `favorite` and `recent_item` hold workspace, owner membership, and `core.record` id (composite FKs). Target types plug in through `NavigationTargetAdapter` (brand, team today), which resolves readability with the same predicates as the target's own read. Lists re-authorize at display and omit unreadable entries silently, removing them in the same request. Writes resolve the target first (forged or foreign IDs: `not_found`). Favorites: idempotent add, advisory lock per person, bounded fractional ranks with rebalancing, refusal at `FAVORITES_MAX` (`limit_exceeded`). Recents: written only by the client after a successful authorized render, coalesced inside `RECENT_VISIT_COALESCE`, and trimmed to `RECENT_ITEMS_MAX` in the same transaction; failures never block the page. |
| E8 | View state (NAV-011) | Each registered view declares its allow-listed fields and where each lives: `url` (filters, sort; shareable, replaced on change), `device` (stored per person, device, and view; restored next session), or `session` (selection, scroll anchor for this tab). Decoding builds fresh objects from allow-listed keys, so prototype or key injection is impossible; wrong version, oversize, or malformed input is rejected on write and degrades to defaults on read. The device is an opaque 32-byte browser key, stored only as a SHA-256. Writes are last-write-wins per device, with optional `If-Match`; rows expire after `VIEW_STATE_TTL`. Scroll is restored by anchor item, then former position. Selections are pruned to visible items before any bulk action, with a polite announcement. |
| E9 | Preferences | One typed contract: account-scoped values (theme, density, motion, shortcuts, start page, record opening, hidden destinations) in `identity.account_preference` with row versions; one device-local value (sidebar) in local storage. Appearance is cached locally and applied before first paint by a same-origin blocking script (`theme-init.js`; no CSP exception). It follows the operating system live only in System mode. |
| E10 | Commands and shortcuts | One registry of commands (stable id, label, group, optional shortcut and layer, telemetry id, and either a link or an action). Components register commands only when the principal may use them, so the palette, shortcut reference, and menus never show unavailable items. The palette orders groups Actions, Go to, Records (implemented types via the target adapters), Recent; `>` restricts to actions; consequential commands open their normal forms. One document listener handles layers (inner focus wins); ignores repeats, IME composition, and anything behind a modal; suppresses single-key and sequence shortcuts in editable fields or when turned off; and uses Command on Apple platforms and Control elsewhere. |
| E11 | Key map | Ctrl/⌘+K palette; Ctrl/⌘+Shift+B scope switcher; `?` reference; G then H, T, I, W, P, C, K, O, R destinations; G then V recently viewed. F6 region cycling (RS-12's proposal) fails the A11Y-KB-07 conflict rule (browser function key), so region moves are skip links ("Skip to main content", "Skip to navigation") plus permission-filtered palette actions; the 0E sources were reconciled accordingly (A11Y-KB-04, RS-12, RS-33, A11Y-PA-11), with A11Y-KB-07 controlling. `/` search and `C` capture are absent until search (5A) and capture (2E) exist. A validator test enforces the conflict rules. |
| E12 | Later destinations | Today, Inbox, My Work, Projects, Calendar, Knowledge, Goals, and Reports are real, scope-sensitive routes that state honestly that the destination arrives later. They show no data. Notifications are an honest "not available yet" popover; the activity tray is absent (nothing runs); quick capture is absent. |
| E13 | Not available (ST-41) | Unknown addresses, missing or unauthorized workspaces, and any page resource returning `not_found` switch the whole page to one state: heading "This page isn't available", the same copy, and the title "Not available · PM". |
| E14 | Telemetry | `POST /v1/shell/events` counts only registry command ids with trigger, and client decode failures with allow-listed sources and reasons. Personal lists produce no outbox events, and recent or view-state churn is never audited. No preference changes authority or exposure, so preference changes are counted (`identity.preference_updates`), not audited. |
| E15 | Lifecycle and retention | Every record type registered by tenancy is wrapped so a purge also removes personal references. `PersonalDataRegistry` holds the views (membership) and identity (account) erasers for departure retention and the future account-deletion command. The hourly `views.cleanup` job discovers workspaces through a dispatcher definer function. It removes expired view state and, once an R-PERSONAL period is configured, departed members' personal rows. |

## Deviations and limitations

| # | Item | Disposition requested |
|---|---|---|
| F1 | IA-04 sends single-brand members to My Work; in this release a destination with later-phase content is never the automatic landing, so members land on Home (or their chosen start page) | Accept until My Work exists (3B) |
| F2 | Guests have no navigable record pages yet (fixture record types only), so the guest Compact bar has Shared with me, Recent, and More instead of five slots | Accept; owning phases add record pages |
| F3 | A multi-brand scope is stored per device only; the membership row keeps the last single-brand or all-brands choice (directory contract from 1C) | Accept |
| F4 | Saved views and admin pins: `views.view_pin` schema, read path, and authorization hook only; application roles cannot insert pins until the view engine grants it | Owning view phase |
| F5 | Palette Records covers brands and teams only; search proper is 5A | 5A |
| F6 | RS-12's F6 region cycling is replaced (E11; normative 0E text reconciled). Screen-reader runs with NVDA, JAWS, and VoiceOver (A11Y-KB-07 rule 5) are manual and not part of automated acceptance | Schedule manual AT pass (11E) |
| F7 | The Compact search-sheet "Favorites"/"Recent" placement is served by the More sheet and the palette's Recent group | Accept |
| F8 | Departed members' personal rows wait for a configured R-PERSONAL period (OD-39); expired view state is always removed | Product decision OD-39 |
| F9 | The shortcut "auto" default uses `(pointer: fine)` at load; a hybrid device switching pointers mid-session keeps the initial choice until reload | Accept |

## Consequences

Every later phase adds a route by registering it (pattern, section, placement, permission predicate) and mapping a component. It adds palette entries by registering commands, makes records favoritable and recent-capable by registering a `NavigationTargetAdapter`, and gets view-state persistence by declaring a view schema in `@pm/contracts/shell`.
